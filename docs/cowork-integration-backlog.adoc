= AgentExtension integration backlog
:toc:
:toclevels: 1

Baseline *AgentExtension 0.5.0*, verified on 9 November 2026. On 11 November 2026, ten further milestones were implemented and verified on top of 0.5.0. They have not been released. The package version is still 0.5.0. link:milestones.md#verification-record-for-the-11-november-milestones[Verification record]

The five milestones in the research plan shipped in 0.5.0. They cover scoped permissions, skills and context sources, workspace notes and read connectors, versioned local plugins and two read-only subagents, and browser inspection with saved run reports. The release also includes scoped macOS computer use. link:claude-cowork-research.md[Cowork research] · link:milestones.md[Release and verification record]

== Features with a partial integration

[cols="1,2,3",options="header"]
|===
|Area |What is implemented |What remains

|Permission policy
|The broker binds approvals to the run, workspace, action, and target. Users can revoke access. Allow, ask, and deny rules come from three sources: an administrator policy file, user settings, and workspace rules kept in extension storage. Administrator deny and ask rules apply first. An invalid administrator file blocks runs. link:milestones.md#permission-rules[Details]
|Read administrator rules from VS Code's managed policy channel or an organization service instead of a file. Add rules for connector writes and account changes when write connectors exist.

|Skills
|Users select text workflows from approved roots. Up to two eligible skills are matched to the request automatically, within a 12,000-character budget. Explicit-only skills stay manual. link:milestones.md#automatic-skill-matching[Details]
|Let the model choose a skill from the catalog during a run, instead of only lexical matching at the start. Add isolated skill execution after its runtime and permissions can be verified.

|MCP connectors
|Approved remote tools can read named targets. Reads ask for approval each time or follow permission rules. VS Code stores bearer credentials.
|Add OAuth sign-in and account selection. Define approval rules for connector writes and account changes. Consider separately approved local MCP processes.

|Plugins and hooks
|Local plugins declare a version, capabilities, skills, worker roles, custom read-only roles, and connector references. Changes to the approved content require review. The bundled `fix-team` plugin adds diagnosis, edit-proposal, and a custom reviewer.
|Add validated package imports, a catalog or shared distribution, and namespaced workflow commands. Add built-in hooks for validation or events. Custom hooks need a separate executor with limits on input, time, and output.

|Instructions and context
|Opt-in user and workspace instruction profiles and path-scoped rules are available. Workspace files must be approved by digest. Reports record the instruction version. **Context sources** totals characters by source. The run shows TrueForge's input-token breakdown and compaction count. link:milestones.md#instruction-profiles-and-path-rules[Details]
|Show which context survives compaction. TrueForge reports that compaction happened and its token use, but not what it kept.

|Memory
|Workspace notes and user preferences are separate approved stores. Notes can be edited in place and cite source files. Agent-suggested notes wait in a third store until the user saves, edits, or discards them. link:milestones.md#notes-preferences-and-suggested-notes[Details]
|Search or summarize notes when a store reaches its limit. Add memory that can be shared across devices.

|Subagents
|Read-only research, diff review, and test diagnosis roles are available. Plugins can declare custom read-only roles. An edit-proposal worker drafts in a separate draft. The parent merges only onto the same base revision with no overlapping changes, and the user reviews every hunk. link:milestones.md#diagnosis-edit-proposal-and-custom-workers[Details]
|Allow custom roles to use tools, each with an explicit read-only tool scope. Allow workers in scheduled reports within the schedule pin.

|Browser and computer use
|A fresh browser profile uses approved origins and exact action approvals. One read-only visit outside the scope can be approved, with a limit of three per run. The macOS helper can inspect and act on accessible controls in one selected app. link:milestones.md#one-approved-visit-outside-the-browser-scope[Details]
|Review support for more browser file transfers and native controls that require screen-based interaction. Keep scope and stop controls for each capability.

|Scheduled reports
|Approved recurring read-only runs use an IANA time zone, a budget, and a pinned scope that includes connector targets. Run history, catch-up after VS Code restarts, offline and blocked outcomes, and per-occurrence claims are included. Scheduled runs have no write tools. Permission rules apply. link:milestones.md#scheduled-read-only-reports[Details]
|Run schedules when VS Code is closed. This needs a background service or a TrueForge-hosted connector. Add a token limit using the usage TrueForge now reports. Allow selected skills, instructions, and read-only workers within the schedule pin. Add a notification channel outside VS Code. Exercise the schedule UI in the VS Code interface harness.

|Audit and usage
|Runs track tokens, tool calls, and time across the parent agent, workers, and compaction against a configurable budget. Decisions and run summaries go to a hash-chained log for each workspace, with a redacted, verifiable export. link:milestones.md#run-budget-and-audit-export[Details]
|Collect exports centrally for an organization. Add cost estimates when the model provider reports them.

|Questions during a run
|The agent can pause with TrueForge's question tool. The panel shows the question and up to five options. The user can choose an option, type an answer, or skip. Questions are kept separate from approvals and limited to five per run. link:milestones.md#questions-during-a-run[Details]
|Support questions in scheduled reports by holding them for the next interactive session.

|Run checkpoints and recovery
|A checkpoint saves the request, plan, staged draft, checks, and progress without grants. After a restart or failure, **Resume** checks the workspace, restores the draft in a new session, and asks again for every protected action. link:milestones.md#run-checkpoints-and-recovery[Details]
|Reattach to the original TrueForge session instead of starting a new one. Checkpoint inline edits.
|===

== Capabilities still open

[cols="1,3",options="header"]
|===
|Capability |Remaining work

|Cross-device sessions and remote task assignment
|Use checkpoints as the basis for continuing a run on another device. Remote control needs device identity, revocation, and a defined offline recovery path. This needs a hosted service.

|Shared projects and administration
|Add shared instructions, files, and memory with roles for viewing and editing. Add organization controls for tool access, network access, trusted devices, and audit visibility. This needs a hosted service.

|Editable artifacts and office files
|Saved Markdown reports cover run evidence. Editable interactive artifacts and workflows for documents, spreadsheets, and slides remain research options.
|===

== Research options with no release commitment

* Automatic screening of actions and a mode that skips prompts. The shipped broker uses explicit approvals for protected actions.
* A managed cloud runner or a broader virtual machine boundary. The extension runs against local TrueForge and uses separate controls for commands, browser access, and native app access.
* Computer-use teaching and recording. The research found desktop code paths for these features. Runtime behavior was outside that inspection.

== Verification still open

Run a compatible general coding model through the same workflows to check tool choice and task quality. The 0.5.0 tests verified the extension with scripted model responses, including real browser and native app operations. Flask Task B passed with a scripted fixture. A successful live-model run remains open. The 11 November milestones were also verified with scripted responses.
