# AgentExtension features

AgentExtension 0.6.1 is a VS Code coding agent powered by a local TrueForge server. It proposes changes in a draft. You review the changes in VS Code and choose which ones to apply. It requires a trusted local workspace, VS Code 1.101 or later, and a model configured in TrueForge. [Extension manifest](../package.json) · [Setup](../README.md#set-up)

## Coding and review

- **Agent sidebar.** Describe a task in the prompt at the bottom of the sidebar. Follow the response, questions, plan, and review in the same panel. Use **Workspace** to open settings for the current workspace and **Run details** to see what happened during the run. [Sidebar](../media/panel.js) · [VS Code entry point](../src/extension.js)
- **Inline edit.** Select code and run **AgentExtension: Edit Selection**. Use `Cmd+Alt+I` on macOS or `Ctrl+Alt+I` on Windows and Linux. The draft can change only the original selection. [Commands and shortcuts](../package.json) · [Draft editing](../src/draft.js)
- **Repository-wide edits.** Ask the agent to search and read the workspace, change several files, or create a text file in an existing folder. The extension stages exact text replacements and line edits in memory. Whole-line edits can use a literal line array and insert after an exact source anchor. Current source receipts and hunk review still apply. [Editor tools](../src/bridge.js)
- **Plan first.** Review the goal, steps, and proposed checks. Approve the plan before the agent can stage edits or run commands. [Plan tools](../src/bridge.js) · [Approval flow](../src/forge.js)
- **Questions during a run.** The agent can pause to ask up to five questions. Choose an option, enter a custom answer, or skip the question. Tool approvals use separate controls. [Question handling](../src/forge.js)
- **Fix from Problems.** Choose **Fix with AgentExtension** from the Quick Fix menu. The agent uses the diagnostic and its source location to propose a plan and stage a fix for review. [Quick Fix](../src/extension.js) · [Editor tests](../test/editor-features.test.js)
- **Diff preview and hunk decisions.** Open a full-file diff or preview one hunk in the VS Code diff editor. Accept or reject each hunk, then send those decisions back to the agent. [Review panel](../media/panel.js) · [Run controls](../src/extension.js)
- **Apply and undo.** Apply the accepted hunks after review. The extension checks that the underlying text still matches, edits existing files in VS Code, and creates approved new files. **Undo last apply** reverts the batch if the affected files still match the applied result. [Apply implementation](../src/apply.js) · [Undo command](../src/extension.js)
- **Verification commands.** Review the proposed executable, arguments, and draft scope. Checks run in a temporary workspace copy with network access blocked. After review, **Check accepted changes** reruns a recorded command with only accepted hunks. The panel flags stale results when the checked draft or file contents change. Isolated checks work on macOS and on Linux with bubblewrap. [Check tools](../src/bridge.js) · [Command isolation](../src/workspace.js)
- **Bounded completion follow-up.** An unchecked draft gets one request to finish missing work and verify it before apply. Empty responses and promises of future work each get at most one continuation. Planning-only requests retain their no-edit scope. External writes prevent these automatic continuations. The panel and saved task state show missing verification. Version and help probes cannot count as project checks. Edit results include bounded draft previews to help the agent inspect structure and indentation. [Completion flow](../src/forge.js) · [Task evidence](../src/recovery.js)
- **Working-tree review.** Select up to six changed text files for a read-only review against Git `HEAD`. A worker returns findings for that snapshot. The extension marks the findings stale if the selected files change during review. [Git comparison](../src/git-review.js) · [Review tests](../test/editor-features.test.js)

## Context and workspace preferences

- **Automatic repository context.** The extension uses identifier-aware lexical ranking and exact path/symbol matches. A private incremental index can include source, tests, and documentation. Fresh search overlays unsaved and staged text. Literal, word, path, glob, and optional bounded-regex queries report coverage. Explicit relationship lookup labels inferred imports, tests, and documentation links. Line edits require current read receipts. [Context ranking](../src/context.js) · [Editor tools](../src/bridge.js)
- **File and symbol context.** Use **@ Context** or type `@file:` and `@symbol:` references. VS Code language providers can add definitions and references for symbols and diagnostics. Keyword search supplies context when the providers return no results. [Editor context](../src/editor-context.js) · [Context ranking](../src/context.js)
- **Context source history.** See the source, trust label, reason, and size of recorded context entries. The panel marks entries recorded before or after the latest completed main-thread compaction. The saved report records counts and the compaction's token usage. Per-source retention is unavailable. [Prompt and context history](../src/prompt.js) · [Sidebar](../media/panel.js)
- **User and repository instructions.** Set standing user instructions. Approve repository instructions from `AGENTS.md` or `.agentextension/instructions.md`, and add file-specific rules under `.agentextension/rules/`. Changes to repository instructions require fresh approval. [Instruction loading](../src/instructions.js)
- **Local skills.** Select text workflows from approved folders, including the bundled `focused-change` skill. The agent can match and request eligible skills when automatic skills are on. The run allows three active skills. Explicit-only skills require manual selection. [Skill registry](../src/skills.js) · [Bundled skill](../skills/focused-change/SKILL.md)
- **Isolated scripts and hooks.** An active skill can request an approved standalone Node.js script. An enabled plugin can run a pinned custom hook after a check or before applying accepted changes. [Skill scripts](../README.md#isolated-skill-scripts) · [Custom hooks](../README.md#custom-plugin-hooks)
- **Notes and preferences.** Search saved notes by text, scope, or cited file. Free space by replacing selected notes or preferences with a shorter summary after review. The agent can suggest notes for you to save, edit, or discard. [Notes and suggestions](../src/memory.js)

## Plugins and workers

- **Versioned local plugins.** Approve plugins for a workspace after reviewing their publisher, version, content digest, and capabilities. Plugins can add skills, worker roles, and references to configured connectors. A change to approved plugin content or its referenced connector configuration requires fresh approval. [Plugin registry](../src/plugins.js)
- **Shareable plugin packages.** Export a plugin as a JSON file and import it from a shared folder. The extension validates the package before it publishes the new version. Workspace approval is a separate step. [Package controls](../README.md#plugin-packages-and-workflows)
- **Named plugin workflows.** Choose a workflow from an approved plugin or invoke its command ID. Review or edit its prompt, then start a run with the usual plan, tool, and edit approvals. [Workflow controls](../README.md#plugin-packages-and-workflows)
- **Research and review workers.** The bundled `review-team` plugin adds repository research and draft review. Workers inspect limited snapshots in separate TrueForge sessions and return findings with source references. [Review plugin](../plugins/review-team/plugin.json) · [Worker implementation](../src/workers.js)
- **Scoped worker reads.** Approved custom repository roles can read more lines from files the parent named. Reads use captured text and end with the worker session. [Worker tools](../README.md#local-plugin-setup)
- **Built-in hooks.** Approved plugins can record isolated check outcomes and block apply when accepted changes contain possible merge conflict markers. The saved report records each result. [Hook setup](../README.md#built-in-plugin-hooks)
- **Test diagnosis and edit proposals.** The bundled `fix-team` plugin can diagnose a failed check, draft a fix in a separate draft, and run a custom documentation review. The parent agent can merge a proposal when the draft revision still matches and the changes do not overlap. Merged changes go through hunk review. [Fix plugin](../plugins/fix-team/plugin.json) · [Worker implementation](../src/workers.js)

## Connectors, browser, and desktop

- **MCP connectors.** Enable read tools and approval-only write tools for specific targets. Use a bearer token or sign in to a compatible OAuth issuer. Writes require approval for the exact server, account, tool, target, and arguments. Scheduled reports expose reads only. [Connector implementation](../src/connectors.js) · [OAuth accounts](../src/connector-oauth.js)
- **Local MCP reads.** Enable a standalone Node.js server by file and SHA-256 in user settings. Each interactive read starts an isolated process on macOS or Linux and needs approval for one configured tool and exact target. [Setup](../README.md#local-mcp-over-stdio) · [Verification](remaining-work.md#verification-completed)
- **Browser inspection.** Open approved sites in a fresh Chrome or Chromium profile. The agent can read page text, inspect visible controls, and request screenshots. It can also request a temporary read-only visit to an exact URL outside the approved origins. [Browser implementation](../src/browser.js)
- **Browser interaction.** In interaction mode, the agent can request a click, enter text, or upload a workspace text file through a visible control. Browser actions and outgoing write requests have separate permission checks. [Browser actions](../src/browser.js) · [Access checks](../src/surface-access.js)
- **Browser downloads.** Approve a direct, same-origin text attachment and its new workspace path. The host can stage up to 64,000 bytes of UTF-8 text for hunk review. The user applies the approved hunk to create the file. [Browser download](../src/browser.js) · [Draft editing](../src/draft.js)
- **macOS computer use.** Select one running app on macOS 13 or later. The agent can inspect its first accessible window and request a press, text entry, or one increment on a supported slider. The helper binds the action to the observed window and control. This feature requires macOS accessibility access. [Desktop integration](../src/computer.js) · [Accessibility helper](../native/desktop.swift)

## Run controls and records

- **Scoped permissions.** Administrator, user, and workspace rules can allow, ask about, or deny supported actions. One-time grants expire and apply to a specific run, workspace, and action. The panel lists recent decisions. [Permission broker](../src/permissions.js) · [Rule engine](../src/policy.js)
- **Organization policy.** Enrolled workspaces use authenticated administrator rules from an organization service. The editor checks the current rules before protected actions. [Organization setup](../README.md#organization-policy-and-audit)
- **Cancel and revoke.** Cancel an active run, discard a completed draft, or revoke the run's access. **Stop browser and computer** ends external access while editor work can continue. Changes to remote sites and native apps take effect during the approved action. [Run controls](../src/extension.js)
- **Model settings and fallback.** Choose a primary TrueForge model and an optional fallback. The extension streams responses, links to the session, and can compact long histories. On an eligible model error, it tries the fallback once or retries the primary model once. A user-approved surface action, a native action dispatch, or a connector write dispatch ends retry eligibility. [TrueForge session handling](../src/forge.js)
- **Checkpoint and recovery.** Resume an interrupted agent or inline run. Recovery preserves the inline selection and independent file edits. Preview overlapping changes before choosing what to stage. The extension reconnects to the original TrueForge session after a completed turn when the previous editor connection has closed. It can also restore the draft in a new session. Protected actions require fresh approval. [Checkpoint implementation](../src/checkpoint.js) · [Recovery tests](../test/extension-checkpoint.test.js)
- **Run usage and limits.** See model tokens, tool calls, elapsed time, compaction activity, and the estimated cost in USD when TrueForge reports it. Usage includes separate worker turns. Cost also appears in saved reports. Configurable limits restrict further tool calls while keeping draft review available. [Usage tracking](../src/usage.js) · [Reports](../src/reports.js)
- **Saved run reports.** Reopen a local Markdown report after VS Code restarts. It can link to the draft, the exact patch used in each check, worker sessions, and captured browser screenshots. The extension retains up to 20 run report folders per workspace. [Report generation](../src/reports.js)
- **Audit export.** Export a redacted JSON record of permission decisions and run summaries for the current workspace. Export all retained events or limit the export to the last 7 or 30 days. The export includes a check of the record's hash chain. [Audit log](../src/audit.js)
- **Organization audit sync.** An enrolled workspace can send verified redacted events to its approved collector. Retries skip records already accepted. The editor shows the last sync result. [Collector setup](../README.md#organization-policy-and-audit)
- **Shared project pilot.** Approved devices can share versioned notes and instructions with viewer and editor roles. Editors can resolve concurrent edits in a VS Code diff and assign a saved draft to another device. The recipient needs matching Git and file revisions and must review and apply the hunks locally. The service records project changes by user and device. [Shared project setup](../README.md#shared-project-pilot)
- **Workspace file sync.** Enrolled editors can publish selected saved text changes from across a checkout. Project members can review and apply additions, edits, deletions, and reversions from a matching Git base. [File sync setup](../README.md#sync-workspace-files)
- **Cross-device session continuation.** Two enrolled editor devices for the same user can share a reviewed request, recent progress, and staged text. The recipient imports the checkpoint and starts a new local TrueForge session by selecting **Resume**. [Continuation setup](../README.md#continue-a-trueforge-session-on-another-device)
- **Private memory sync.** Sync personal preferences and workspace notes on separately enrolled devices for the same user. Work offline, merge independent edits, and choose a version when both devices change the same note. [Memory sync setup](../README.md#sync-personal-preferences-and-workspace-notes)

## Scheduled reports

- **Recurring read-only reports.** Choose days, times, a time zone, a prompt, and a budget. Runs can read workspace files and approved connector targets. Budgets cover time, tool calls, connector reads, and model tokens. [Schedule controller](../src/schedule-controller.js) · [Scheduled run](../src/scheduled-run.js)
- **Local background runner.** A separately approved schedule can run while VS Code is closed. The runner and editor share occurrence claims and history. An OAuth schedule uses a separate refresh credential tied to the approved account and scopes. The runner can send an approved webhook notification with the outcome and report location. [Runner setup](../README.md#run-reports-with-vs-code-closed)
- **Approved report context.** Choose instruction profiles, skill bodies, and read-only repository workers for a schedule. The extension checks the approved versions and pauses the schedule if a selection changes. [Schedule setup](../README.md#scheduled-reports)
- **Deferred questions.** A report can save one question to its history. Review it in the Agent panel, dismiss it, or answer it to start a new interactive run. [Question controls](../src/schedule-controller.js)
- **Schedule management and history.** Run a schedule now, pause it, approve it again, view its history, or delete it. The scheduler handles time changes and can catch up on the latest missed occurrence within its configured window. Changes to approved settings or credentials require fresh approval. [Scheduler](../src/schedules.js) · [Schedule controls](../src/schedule-controller.js)
